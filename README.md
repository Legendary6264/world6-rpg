# Грани Бытия

Ролевая платформа для игры в Мире 6. Канон игрового мира сохраняет своё название.

React/Vite-клиент и Node.js API для общего форума, лобби, чата и кампаний.
Сайт: https://legendary6264.github.io/world6-rpg/
API: https://world6-api.onrender.com/api/health

## Совместная игра от начала до конца

[Пошаговый запуск и игра с другом](docs/play-with-friend.md): создание кампании, приглашение, герой, открытие сцены, раунды, перерыв и общий финал. На игровом столе видны готовность и фаза игры; завершение сохраняет итог в чат и финальный снимок одной операцией. Позиции и знания после закрытия доступны для чтения.

Локально: `npm ci`, затем `npm run dev:all`. Для двух устройств в одной частной сети — `npm run dev:lan`; адрес второго устройства появится в терминале. Для интернет-игры сайт и API должны быть развёрнуты совместно.

## Роли сайта

| Роль | Полномочия |
| --- | --- |
| Игрок | Свои персонажи, участие и создание лобби, форум, сюжеты, свои обращения в поддержку |
| Редактор мира | Возможности игрока; создание и изменение собственных черновиков справочника |
| Администратор | Новости, модерация, поддержка, публикация материалов справочника, блокировка обычных аккаунтов |
| Владелец | Возможности администратора, назначение ролей и управление администраторами |

Глобальной роли GM нет. Устаревшие аккаунты GM переводятся в PLAYER при запуске.
Привилегированные действия требуют подтверждённого TOTP через Supabase MFA.
Игрок может настроить второй фактор добровольно; если он настроен, вход требует кода.
Регистрация открыта, сервер не доверяет роли из данных регистрации или user_metadata.

## Роли в лобби

- Главный ГМ: настройки, набор, приглашения, исключение участников, назначение помощников и передача главного ГМ.
- Помощник ГМ: только разрешения, выданные главным ГМ для конкретного лобби. Полный редактор требует всех разрешений; составом и настройками управляет главный ГМ.
- Игрок: чат, собственные герои и доступные персонажу сведения.

Любой аккаунт может создать лобби. Администратор и редактор мира не получают доступ к чужим кампаниям автоматически.
Передача главного ГМ выполняется атомарно: новый ГМ должен быть активным участником этого лобби,
прежний ГМ становится помощником, код приглашения меняется, кампания и чат сохраняются.
Помощники не занимают места для игроков. Для возврата помощника в игроки нужно свободное место.
Закрытое лобби хранит историю; его можно снова открыть через настройки.

## Материалы мира

Раздел «Редактор мира» доступен редакторам и администрации. Черновики не видны публично.
Публикует их администратор или владелец после проверки; материалы появляются в «Путеводителе».
Редактор не может напрямую менять опубликованный канон или чужой черновик.
Изменения защищены номером версии, действия публикации и управления записываются в аудит.
Игровые формулы и существующий канон не меняются этими настройками.

## Редактор сцен кампании

В лобби открой «Редактор» → «Открыть сцены в редакторе». Мастер и помощник с разрешением на сцены используют один конструктор: 3D/схема, библиотека, свободное размещение и сетка, группы, собственные сборки, импорт/экспорт и отмена изменений. Кнопка «Открыть редактор сцены» доступна также на игровом столе.

Можно собрать сцену с нуля или добавить отдельную таверну из примера. Сохрани сцены на сервер, перейди к игровому столу и используй «Начать игру на сцене», чтобы разместить принятых героев и явно выбрать открытые им сведения. Прямая передача расстановки включается отдельно; она сохраняет завершённые изменения в пределах раскрытого игрокам обзора. При новой серверной версии черновик сохраняется, а передача приостанавливается. Кнопка «Сверить с сервером» объединяет независимые правки и предлагает выбор спорных изменений. Сначала прими согласованный черновик, затем отдельно сохрани его на сервер; до правки или записи согласование можно отменить. Подробности: [docs/scene-draft-merge-review.md](docs/scene-draft-merge-review.md).

В «Параметры сцены» → «Копия сцены» можно создать второй зал или вариант готовой комнаты. Копируются все предметы, фон и сохранённые параметры; сцена и предметы получают новые ID. Герои остаются в исходных сценах. Создание отменяется и возвращается одним действием. Временное скрытие и защита редактора остаются только у исходной сцены. Подробности: [docs/scene-copy-review.md](docs/scene-copy-review.md).

В свойствах стола или другой плоской опоры доступны «Перенести с содержимым», «Копировать с содержимым» и «Дублировать с содержимым». Они включают предметы на поверхности и вложенных опорах. Shift+G выделяет предметы для поворота, масштаба и сохранения в сборку; герои следуют за своими опорами, а копии содержат только предметы. Скрытая или защищённая часть блокирует общее действие.

После Ctrl+V можно включить «Повторять вставку» и расставлять копии нажатием на сцену. Угол и высота сохраняются. «Отменить вставку» / Ctrl+Z и «Вернуть вставку» / Ctrl+Shift+Z работают внутри текущей расстановки. Esc или «Завершить вставку» выделяет последнюю оставшуюся копию. Каждая новая вставка начинается в обычном однократном режиме.

«Создать ряд» в панели вставки позволяет задать число копий, ось X/Y сцены и промежуток между краями композиций. R поворачивает каждую копию, сохраняя ось ряда. Весь ряд виден в предпросмотре, размещается и отменяется одним действием; его можно повторять и сохранить в сборку. В одном ряду — до 64 объектов, доступное число копий показано в панели.

В режиме «Схема» модели каталога имеют собственные обозначения сверху и сбоку: мебель, посуда, свет и строения различаются по рисунку. Автоматические обозначения учитывают поворот, открытие и состояние огня. На карте игрока сохраняются раскрытые и запомненные состояния; выбранные изображения и напольные узоры продолжают использоваться.

Листы и общие настройки кампании доступны ниже в отдельном полном редакторе для мастера и полностью уполномоченного помощника. Пробы неканонических способностей остаются в изолированном полигоне. Статус интеграции и проверок: [docs/editor-integration-review.md](docs/editor-integration-review.md).

## Запуск

Требуется Node.js 24. Установить зависимости: `npm ci`.
Локальная проверка: `npm run dev:all` (клиент 5173, API 3001).
Для разработки можно создать `server/.env` на основе `server/.env.example`.
Локальная SQLite создаётся автоматически; production требует PostgreSQL и Supabase Auth.

Все локальные проверки: `npm run verify:local`. Команда последовательно проверяет сам запуск проверок, правила, UI, сервер, lint и сборку. Логи и JSON-результат сохраняются в новом каталоге `.verification/`; ошибка любого шага даёт ненулевой код завершения, остальные шаги продолжаются.
Для тестов требуется завершённый TAP-отчёт со всеми пройденными сценариями: одного кода процесса `0` недостаточно.
Отдельно: `npm test`, `npm run test:ui`, `npm run test:server`, `npm run lint`, `npm run build`.
Серверные тесты используют изолированные SQLite и PostgreSQL (PGlite), а тесты Supabase — отдельный тестовый Auth-сервис.
Облачная регистрация, письма и реальные TOTP-коды проверяются отдельно через аккаунт пользователя.
Сквозная приёмка и ограничения текущей копии: [docs/product-acceptance-plan.md](docs/product-acceptance-plan.md). Успешные локальные проверки не означают готовность всего продукта.

Совместная кампания: после сбора заявлений мастер задаёт бюджеты и стоимости действий, рассчитывает последствия и отдельно применяет раунд. Незавершённая работа и подготовка переносятся. Доступны сцены, индивидуальные знания, NPC, имущество и торговля, пауза, контрольные точки, архивы, откат и переигровка. Учебная площадка изолирована от реальных лобби.

Визуальная библиотека содержит 720 оригинальных SVG: поверхности и фоны, окружение, предметы, портреты персонажей и существ. Персонажи отображаются портретами на токенах. Для способностей доступны 60 семейств анимированных эффектов с предпросмотром, паузой и повтором. Использование и границы проверки: [docs/expanded-assets-and-effects.md](docs/expanded-assets-and-effects.md).

Текущий выпуск подготовлен без встроенного голосового чата. Текстовый чат лобби, игровые реплики с подтверждённой мастером слышимостью и личные журналы доступны. Микрофон, WebRTC и TURN в этом выпуске не используются. Границы проверок и порядок первой игры: [docs/release-no-voice.md](docs/release-no-voice.md).

## Публикация

GitHub Pages собирается workflow `.github/workflows/pages.yml` из `main`.
Переменная репозитория `VITE_API_URL` должна содержать `https://world6-api.onrender.com`.
Необязательная переменная `VITE_SITE_URL` задаёт canonical/OG-адрес страницы; без неё основной адрес в метаданных не объявляется. Сборка проверяет публичные URL.
Render автоматически обновляет API из `main`, сборка: `npm ci --include=dev && npm run server:build`, запуск: `npm start`.
Переменные Render: `NODE_ENV=production`, `AUTH_MODE=supabase`, `DATABASE_URL`, `SUPABASE_URL`,
`SUPABASE_PUBLISHABLE_KEY`, `OWNER_USER_ID`, `CLIENT_ORIGINS=https://legendary6264.github.io`.
URL сайта для email-переходов Supabase должен разрешать `https://legendary6264.github.io/world6-rpg/`.

Таблицы находятся в приватной схеме `world6`; браузер обращается к ним через API.
RLS и запрет PUBLIC оставлены включёнными; отсутствие публичных политик в этой схеме намеренно.
Миграции приложения идемпотентны и выполняются при запуске API. Данные пользователей сохраняются в Supabase.
Не добавляйте `.env`, ключи, локальную базу и её WAL-файлы в Git. Секретные ключи Supabase не нужны браузеру.

## Подготовка нового названия и адреса

Название продукта — «Грани Бытия»; ключи хранения, идентификаторы архивов, схема `world6` и адрес API сохранены для совместимости.
Вариант нового бесплатного фронтенда описан в [docs/product-brand-address-review.md](docs/product-brand-address-review.md); конфигурация для просмотра — [deploy/render-frontend.example.yaml](deploy/render-frontend.example.yaml).
Адрес и перенос пока не применены. Новый origin требует входа и ручного переноса локальных черновиков; текущие ссылки должны продолжать работать на время перехода.
