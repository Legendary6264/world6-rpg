# Исправления A1 и A7: черновики редактора лобби

При переходе в другой раздел, смене токена и временной ошибке API редактор раньше
размонтировался вместе с несохранёнными изменениями. Если загрузка мира завершалась
после переключения лобби, её ответ попадал в редактор нового лобби и мог быть
опубликован туда при совпадении версий.

Теперь черновик кампании сохраняется в браузере отдельно по аккаунту и лобби.
Хранятся листы, каталог, часы и исходная серверная revision. Сохранение черновика
не публикует изменения для участников. Публикация по-прежнему выполняется отдельной
кнопкой с серверной проверкой прав и конфликта revision.

`LobbyCampaignEditor` создаётся только для подтверждённого ГМ или помощника и имеет
ключ из пары accountId/lobbyId. Уход из этого редактора отменяет его загрузку;
продолжение запроса дополнительно проверяет отмену и жизненный цикл компонента.
URL публикации берётся из сохранённой принадлежности черновика. Ответ публикации
обновляет только исходный черновик и не заменяет более поздние изменения листов.

Результаты `useRemote` также привязаны к аккаунту: данные прошлого пользователя
не показываются даже при сохранении той же функции request. Подтверждённая потеря
прав закрывает редактор; сохранённый черновик снова доступен после возвращения прав.

При возвращении в раздел нужно открыть нужное лобби — его черновик восстановится
после проверки доступа. Явная загрузка свежего мира требует подтверждения замены
имеющегося черновика. Сохраняются и незавершённые значения полей, которые ещё не
проходят проверку публикации, например пустое имя или временное `-` в числе.

Если браузер запретил хранение или исчерпал место, редактор показывает предупреждение
и сохраняет копию в памяти до закрытия страницы. В этом случае для переноса работы
между открытиями браузера нужен экспорт. Вкладка редактора и неподтверждённый
предварительный расчёт не входят в сохраняемый мировой снимок.

## Ручная проверка перед публикацией

1. От имени ГМ открыть лобби A, загрузить редактор, изменить имя героя без публикации.
2. Перейти в другой раздел, вернуться в лобби A: изменение должно сохраниться.
3. Открыть лобби B, затем снова A: в каждом лобби остаётся собственный черновик.
4. При задержке API начать загрузку A и открыть B до ответа. Поздний ответ A не
   должен появиться в B. Публикация B отправляет только мир B.
5. Проверить переключение аккаунта и изменение роли на PLAYER: прежний редактор
   не должен отображаться. При возврате ASSISTANT его собственный черновик доступен.
6. Из второго клиента изменить серверный мир. Публикация прежнего черновика должна
   получить конфликт, сохранив локальную работу.

Проверка в настоящем браузере с облачным токеном и WebGL остаётся этапом перед
выкладкой. Изменения подготовлены в отдельной ветке; merge и deploy не выполнялись.
