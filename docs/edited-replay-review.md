# R04: переигровка изменённых заявлений

12 октября 2026 года. База этапа: `4832d07bafb7a96acad00fa508a57dba62c00eb5`, ветка `feature/round-timeline-rebuild`. Изменения подготовлены локально. GitHub, Render, Supabase и рабочий сайт не обновлялись.

## Поведение мастера

После отката мастер открывает прежний сбор, игрок исправляет заявление, мастер снова закрывает сбор. В существующей форме исполнения доступны текущие бюджеты, стоимости, параметры способностей, заряды и решения по перенесённой работе. Добавлен выбор бросков для каждого выпуска.

В списке видны прежний герой, способность, цель и порядковый номер действия. Совпадение героя, способности и цели отмечается отдельно. Совпавший номер в новой очереди сам по себе не означает соответствия: мастер выбирает источник явно. Для неоднозначных одинаковых выпусков система не назначает источник автоматически.

Варианты:

- Сохранить броски выбранного прежнего выпуска этого героя и способности.
- Получить новые броски конкретного выпуска.
- Выполнить обычный расчёт всего раунда: при доступном источнике кнопка прямо сообщает, что будут новые броски.

Расчёт показывает выбранный вариант до применения. Изменение выбора скрывает прежний предпросмотр. Черновики разделены по аккаунтам, лобби и сборам; новая версия требует подтверждения решений и заново сбрасывает сопоставление. Пока проверка источника не завершилась, расчёт заблокирован; ошибку запроса можно повторить.

Точная переигровка неизменённого восстановленного снимка с прежними решениями и бросками по-прежнему доступна через историю раундов.

## Идентичность бросков

Сохранение одного зерна генератора больше не используется как замена сопоставлению изменённых действий. Новый расчёт получает новые идентификаторы игровых событий и работ. Выбранные численные значения уворота и крита переносятся из серверной квитанции отдельно от событий и расходов.

Броски записываются по идентификатору получателя. Если первая цель вышла из области, оставшаяся получает собственные значения. Смена порядка отметок не переносит значения между существами. Для новой цели, которой не было среди получателей прежнего выпуска, сохранение бросков отклоняется: мастер должен выбрать новые броски этого выпуска. Сохраняются случайные значения, а результат попадания пересчитывается с текущими шансами, состоянием тела и параметрами.

Один прежний выпуск используется не более одного раза в расчёте. Источник должен принадлежать тому же герою, способности и сцене. Новый герой или другая способность не могут получить чужие броски. Клиент передаёт только выбор источника; значения извлекаются сервером. Подстановка собственных чисел в обычный запрос исполнения отклоняется.

Движок версии `r04-round-history-v8` явно читает предыдущую версию v7. Для старых выпусков без групп целей сохраняются записанные пары по существовавшему порядку получателей; неоднозначные данные не объявляются подходящими. Новые группированные значения записываются в квитанцию и сохранённые параметры расчёта.

## Расходы и безопасность применения

Пересчитывается весь текущий раунд из восстановленного состояния, а не копируется прежний результат. Начальная подготовка оплачивается один раз; готовый заряд выпускается без повторной начальной оплаты. Точные бюджеты, перенос работы, удержание зарядов и прерывания продолжают действовать по существующим правилам.

Используется прежний атомарный механизм применения: текущие полномочия `rounds` и `viewSecrets`, допуск героев, ревизия кампании, поколение, версия сбора, состояние управления и пауза проверяются заново. Отказ записи аудита отменяет всю транзакцию. Потерянный ответ повторяется с сохранённым ключом команды и возвращает прежнюю квитанцию без второго исполнения. Поздние ответы другой комнаты не попадают в текущую форму.

## Сохранение и восстановление

Миграция `010-edited-replay.sql` связывает источник отката с конкретным восстановленным сбором. Повторное открытие и правка сохраняют связь; создание другого сбора её не наследует. Старые установки связывают существующий контекст только при совпадении исходного снимка, без догадки после изменения мира. PostgreSQL: приватная таблица `world6.round_replay_collections`, RLS включён, права PUBLIC отозваны. Всего 39 прикладных таблиц. SQLite и PostgreSQL используют один файл миграции; перезапуск повторяем.

Именованные точки и полная игровая копия версии 2 сохраняют источник изменённой переигровки. Дополнительное поле `replayExact` отличает изменённое состояние от точного снимка: восстановление изменённой точки не разрешает обход сопоставления через старую кнопку точной переигровки. Файлы прежних версий 1/2 читаются; отсутствие этого поля означает прежний точный режим. Новые файлы с этим полем требуют обновлённого сервера. При наличии изменённых контекстов исполнитель не следует заменять старой версией v7: она не различает эти режимы. Операционные идентификаторы при импорте переименовываются, игровые идентификаторы и записанные значения сохраняются.

Параметры уже применённой изменённой переигровки входят в экспорт и могут быть точно повторены после следующего отката. Источник защищён существующим механизмом зависимостей при очистке истории. Владельцы, полномочия, добровольное управление и допуски не импортируются из игровых снимков. Дополнительных платных сервисов нет.

## Восстановление исходников

В полном ZIP лежат все отслеживаемые файлы проекта, а bundle сохраняет историю Git и ветку. Node.js 24 обязателен. После распаковки ZIP либо клонирования bundle установи зависимости командой `npm ci` и запусти `npm run verify:local` с новым каталогом отчёта. Перед прямым запуском `npm start` выполни `npm run server:build`: серверные модули генерируются из актуальных общих TypeScript-правил. Локальные секреты, зависимости и содержимое производственной базы в исходники не входят.

## Границы этапа и следующий результат

Сохранённые броски можно использовать для выпуска, который завершится в текущем раунде. Если изменённый выпуск переносится дальше, расчёт с сохранением отклоняется явно: выбери новые броски либо пересмотри очередь. Это ограничение не округляет время и не стирает выбор молча. Перенос незавершённых действий с новыми бросками работает по прежнему механизму.

Совпадение героя, способности и цели не означает совпадения всех условий: изменённые характеристики и параметры мастер проверяет в текущих формах. Старые установки с уже изменённым неподписанным контекстом до миграции не получают автоматического сопоставления. Для них остаются новый расчёт или повторный откат доступного исходного раунда.

Внешние сессии мастера и двух игроков, телефон, WebGL/3D и производственные Supabase/Render здесь не проверялись. Канон, формулы, локальное здоровье, XYZ, верхний/боковой вид и 3D не изменены. Полноценная готовность продукта и закрытие всех пунктов R04 не заявляются.
