# R07/P21 · игровые экраны и навигация лобби

Продолжение подготовки «Граней Бытия» после `5900bdf`. Использованы готовые R01–R06 и обучение P20; архитектурный аудит повторно не проводился. Изменения локальные, без push, PR, публикации и производственного SQL.

## Что изменилось

Открытое лобби располагается сразу после заголовка. Поиск, создание и список кампаний сворачиваются вместе; кнопка «Найти другую кампанию» возвращает их без закрытия текущего лобби. При закрытии лобби поиск снова показывается. Формы поиска/создания остаются смонтированными.

Основные инструменты разделены на вкладки:

| Раздел | Содержимое и доступ |
| --- | --- |
| Герои | Листы, рассмотрение, экран управляемого героя, индивидуальное раскрытие и управление персонажем; прежние проверки прав каждого инструмента сохранены. |
| Раунд | Приём, время, расчёт/применение и история раундов; необходимы `rounds` и `viewSecrets`. |
| Мир | Имущество, торговля, атлас и разрешённые инструменты NPC. |
| Чат | Общие сообщения участников кампании. Это прежний общий чат; пространственная речь относится к R08. |
| Подготовка | Участники, помощники и их права, условия создания; настройки/приглашения доступны главному мастеру. |
| Редактор | Полный редактор либо разрешённый отдельный редактор сцен. |
| Копии и история | Хранилище истории, полная копия и доступные средства сохранения; необходим `viewSecrets`. |

Внутри экрана героя отдельно доступны «Сцена и действия», «Состояние» и «Журнал». Переключение вкладки скрывает панель атрибутом `hidden`, сохраняя её React-состояние, выбранную отметку, частичные координаты, заметку, открытую форму и текущий запрос/предпросмотр. Доступ к секретам по-прежнему проверяется до создания содержимого панели: скрытая вкладка не является механизмом авторизации. При отзыве разрешений инструмент удаляется, а выбор переходит к доступному разделу. Идентификаторы вкладок/панелей уникальны, есть связи `tablist`/`tab`/`tabpanel`, стрелки влево/вправо и Home/End с переносом фокуса.

На ширине до 760 px вкладки располагаются в две колонки, основные кнопки/поля имеют высоту от 44 px, длинные надписи переносятся, внешние и вложенные отступы уменьшены, сетка полей лобби становится одноколоночной. Поля ввода имеют шрифт 16 px. Общий чат ограничен по высоте экраном, минимум ширины полей конструктора сцены снят. Меню сайта прокручивается горизонтально; аккаунт и состояние связи расположены отдельной строкой, выбранный раздел отмечен `aria-current`.

## Проверки

Добавлены три проверки UI:

1. Переключение основных и внутренних вкладок сохраняет те же DOM-поля, незавершённую координату `-`, заметку, черновик чата и открытый приём; навигация не публикует изменений.
2. Стрелки переводят фокус/выбор; отзыв секретных прав удаляет приём, ограниченный помощник и игрок не получают вкладки полного редактора/копий/раунда.
3. Настоящий локальный HTTP-сервер с отдельной временной SQLite-базой проходит связный сценарий через реальные React-панели: создание примера → вступление по приглашению → отправка облачного героя → рассмотрение/принятие → индивидуальное раскрытие → открытие сбора → заявление ожидания → закрытие → личный бюджет → явная сверка решений → расчёт → переключение вкладок → применение.

В третьем сценарии регистрации, исходный облачный лист и постановка принятого героя на готовую сцену подготовлены через авторизованный тестовый API. Игровые переходы и раскрытие выполняются кнопками/формами UI. До применения мировые часы остаются на нуле; после — ровно 5 с и одна новая ревизия. Повтор той же команды после перезапуска возвращает прежнюю квитанцию без новых последствий. Клиент не отправляет отвергнутых игровых изменений. UI использует JSDOM, а не настоящий браузер; визуальные потомки листа заменены теми же ограниченными заглушками, что в существующем наборе. `test:ui` теперь сначала генерирует общие серверные модули, чтобы HTTP-сценарий воспроизводился из чистых исходников.

Обязательный `verify:local` завершён полностью: 203 сценария правил (53 прежних + 150 TAP), 146 UI, 475 серверных и 6 проверок самого инструмента. Все TAP-отчёты полные, ошибок/пропусков нет. Lint — 0 ошибок и 15 прежних предупреждений; TypeScript и клиентская сборка прошли. Прежнее предупреждение о размере сборочных блоков остаётся. Отчёт запуска: `r07-lobby-navigation-verification-20261012/summary.json`; исходная база проверки `5900bdf`, реализация проверялась до локального коммита. После прогона менялись только этот отчёт/статус и удалялся шум генерации шести отслеживаемых серверных модулей.

## Границы готовности

Правила, канон, исполнитель, XYZ/опоры/свободное движение, адресное раскрытие, серверные права и код 3D не изменены. Скрытый 3D-контейнер использует существующие ResizeObserver и остановку рендера при `offsetParent === null`; реальное WebGL-поведение требует браузерной приёмки.

Проверка на настоящем телефоне/браузере остаётся открытой: установленный Playwright не имеет исполняемого Chromium, а доступный удалённый браузер ранее не смог открыть локальную сборку. Повторять ту же недоступную попытку или публиковать сайт для обхода ограничения не стали. JSDOM/TypeScript не подтверждают внешний вид, сенсорное управление, виртуальную клавиатуру или WebGL.

Следующая приёмка R07/R09: мастер и два независимых игрока, 320/390/768 px, смена ориентации и клавиатура, вход в две кампании, обрыв связи, раскрытие боковой сцены/высоты и WebGL. Затем R08 — серверная слышимость текстовой речи; параметры слуха и схема голосовой связи остаются отдельными решениями O12/O13 из плана восстановления. Полная готовность продукта и выпуск этим изменением не объявляются.

## Запуск сохранённых исходников

Использовать Node 24.x. Из корня проекта: `npm ci`, затем `npm run verify:local -- --output-dir ../checks-new` с новым каталогом. Перед прямым `npm start` выполнить `npm run server:build`: часть общих модулей генерируется из TypeScript и не хранится в Git, а шесть старых отслеживаемых `.mjs` обновляются генератором. Настройки локального сервера описаны в существующих документах; секреты не включены в архив.
