# Задания приключения

Мастер открывает игровой стол → «Ведение приключения» → «Задания героям». Создай задание, заполни текст для игроков и пункты, выбери получателей. Без включённой видимости сохраняется закрытый черновик. «Выдать или обновить задание» публикует его выбранным героям.

Источник выбирается из уже опубликованных реплик мастера и НПС. В личном журнале показывается цитата только той реплики, которую этот герой мог прочитать. Привязка задания не раскрывает чужой разговор. Секретные заметки, остальные получатели и закрытые задания игроку не передаются.

Герой открывает «Экран героя» → «Задания». Доступны текущие поручения, прогресс и история завершённых/не выполненных заданий. Источник помогает вспомнить разговор; кнопка «Открыть разговоры» ведёт в обычный раздел диалогов. Отмечать прогресс и менять состояние может ведущий с разрешениями на НПС и секретные сведения.

Пункты и состояние отмечает мастер по результатам игры. Для состояния «Выполнено» все сохранённые пункты должны быть выполнены; необязательные условия можно заранее исключить из списка. Награды, предметы, расход ресурсов и физические последствия оформляются существующими средствами игры. Прежние общие цели сессии сохраняются отдельно.

## Черновики и конфликты

На устройстве сохраняется отдельный черновик каждого редактируемого задания. Можно переключаться между ними и снова открыть редактор. Несохранённое новое задание можно убрать; местные правки сохранённого задания можно отменить.

Если другой ведущий изменил журнал, отправка требует сверки с текущим сохранённым заданием. Показаны его текст, состояние, прогресс, получатели, источник и заметки. Кнопка сверки сохраняет местный текст и привязывает его к текущей версии; автоматического объединения нет.

Перед отправкой сохраняется точная команда. При потере ответа или неверном подтверждении «Проверить сохранение задания» повторяет её без новой записи. Если хранилище браузера отказало, команда не отправляется. Новое продолжение кампании отвергает команды прежнего поколения. В завершённой сессии журнал остаётся доступным для чтения.

## Хранение и расчёт раунда

Журнал хранится в необязательном `campaign.story.quests`: версия и до 60 заданий, до 12 пунктов в каждом. Старые миры без этого поля читаются как раньше. Новые зависимости и миграции БД не нужны. Полная копия кампании и исходные снимки раундов сохраняют задания вместе с историей.

Версия заданий отделена от плана эпизодов и сообщений. Изменение задания обновляет сохранённую историю в готовом предпросмотре раунда; физический расчёт и броски не выполняются заново. Применяются существующие пределы размеров мира и предпросмотров.

После обновления исходников серверные модули собираются через `npm run server:build`; затем требуется обычный перезапуск API. `npm run dev:all` выполняет подготовку модулей в своём рабочем процессе.

## Проверка

`npm run test:story` включает UI и HTTP-проверки заданий. Они проверяют адресность, источники, секретные заметки, права, повтор команд, конфликт версий, готовый расчёт раунда, перезапуск, архив и завершение игры.

Для отдельной проверки в настоящем Chrome/Chromium/Edge:

```powershell
node scripts/check-quest-journal-browser.mjs .tmp/quest-browser
```

Используется отдельный временный профиль, синтетическая история и настоящие компоненты редактора и журнала. Проверяются публикация, прогресс, история, отсутствие секретных заметок у игрока и ширина 390 px. Скрипт сохраняет PNG и `result.json`; браузер и локальный стенд закрываются. Другой путь к браузеру задаётся через `WORLD6_BROWSER`.
