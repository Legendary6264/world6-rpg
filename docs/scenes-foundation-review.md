# «Грани Бытия»: первый этап — сцены и расстановка мастера

Документ фиксирует первый этап. Доступ помощников и отсутствие делегирования, описанные ниже, заменены следующим этапом: [lobby-access-review.md](lobby-access-review.md).

В кампании появился конструктор сцен: мастер создаёт место, выбирает верхний или боковой вид, размещает окружение и портреты героев. Положение хранится в метрах по X/Y/Z, без сетки. Расстановка сохраняется в текущей кампании и входит в её копии.

Подготовлено в ветке `feature/scenes-foundation` для просмотра. Слияние и публикация на рабочий сайт не выполнялись. Производственная база и настройки GitHub Pages, Render и Supabase не изменялись.

## Что можно проверить

В локальном редакторе персонажей либо в загруженном черновике редактора лобби:

1. Создать сцену, выбрать её оформление и размеры.
2. Выбрать стену, дверь, дерево, камень, контейнер, платформу, источник света или воду; разместить по клику либо в центре.
3. Выбрать объект на карте или в списке; изменить координаты, размеры и признаки препятствия/опоры. Параметры формы применяются кнопкой сохранения.
4. Выбрать героя и разместить его. Портрет берётся из действующего листа.
5. Назначить землю, поверхность объекта или воздух; для воздуха задать Z. Полёт отмечается стрелкой, высотой и тенью; в боковом виде виден уровень относительно земли.
6. Изменить представление сцены: X/Y/Z сохраняются. Перенос героя в другую сцену удаляет прежнее размещение; новый клик явно ставит его на землю выбранной сцены.
7. Вернуться в редактор или другое лобби, экспортировать и восстановить копию с владельцами.

Расстановка мастера не является игровым действием «Идти». Она не считает стоимость, не выдаёт полёт, не лечит тело и не меняет часы. Изменение опоры не назначает автоматическое падение: удалить занятую платформу нельзя до переназначения опоры героя.

## Формат и совместимость

`Campaign.scenes` — необязательное поле `SceneState` версии 1. Прежние кампании без него остаются валидными и не получают новые игровые числа. Внутри — выбранная сцена, массив сцен, объекты и размещения. Координаты и геометрия — метры; Z — высота относительно общего нуля сцены, `groundZ` — высота её земли. Эти единицы согласованы с пользователем перед реализацией.

Опора хранится отдельно от Z. Для земли и поверхности объекта Z соответствует опоре. У героя одно размещение во всех сценах. Физический диаметр отделён от размеров портрета. При изменении занятой платформы положение стоящего героя согласованно меняется вместе с ней; исходный снимок не мутирует.

Проверяются версия, идентификаторы, дубликаты, размеры, конечные координаты, диапазоны высоты, разрешённый фон, ссылки на опоры и на героев. Существующий общий лимит кампании 8 МиБ сохраняется. Начальные размеры новой сцены — редактируемые значения конструктора, не канон. Технические ограничения: до 20 сцен, 250 объектов на сцену и 200 размещений; фактические ссылки ограничены составом кампании.

Данные сохраняются в локальном редакторе, черновике лобби, архиве кампании и копии лобби. Восстановление с владельцами использует существующую транзакцию. При удалении листа или участника с его героями убираются соответствующие размещения.

Публикация старым клиентом, который не передал уже существующие сцены, отклоняется с 409. Для осознанного удаления используется конструктор; явное восстановление прежней полной копии остаётся отдельной операцией.

Игроки пока не получают сцену: серверная проекция возвращает прежние доступные сведения без этого поля. Конструктор доступен существующим редакторам кампании — GM/ASSISTANT. Раздельные полномочия помощников, выдача карты по индивидуальному восприятию и реальное игровое движение относятся к следующим задачам.

## Проверки

- `npm test`: 53 игровых сценария, включая 9 сценариев сцен и сохранение прежних правил.
- `npm run test:ui`: 19 сценариев, включая расстановку, высоту, опоры, переключение лобби, публикацию и сохранение незавершённого листа.
- `npm run test:server`: 63 проверки, включая SQLite/PostgreSQL(PGlite), права, фильтрацию сцен, неверные данные, старый клиент и восстановление владельцев.
- `npm run build`: сборка TypeScript и Vite.
- `npm run lint`: без новых предупреждений; 12 прежних остаются.

UI-проверки используют jsdom и реальные контролы/обработчики. Матрица SVG для проверки координат подставляется; реальный браузер, сенсорный ввод и WebGL в этой среде не проверены. Существующий 3D-код и его ассеты не менялись.

## Границы этапа

Это основа задач P01/P02/P05/P06/P07 ТЗ, а не завершение всей первой версии. Пока нет индивидуальной выдачи карты, автоматического обзора/света, движения игроков, новых раундов, делегирования персонажа, переигровки и игрового/голосового чата.

Ассеты окружения — небольшой оригинальный набор SVG с пиксельными формами. Большая библиотека окружения и учебная кампания ещё впереди. Фон использует существующую обработку изображений с уменьшением и лимитом размера; отдельное хранение больших карт пока не внедрено.

Канон, числа движка, характеристики, способности, тело и 3D сохранены. Новых зависимостей, платных ресурсов и миграций БД нет. `server/generated` создаётся командой `npm run server:build`; исходными для новых правил являются файлы в `src`. Для локального запуска с API используется `npm run dev:all`.
