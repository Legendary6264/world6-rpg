# «Грани Бытия»: полномочия помощников и передача героя

Следующий этап после конструктора сцен, подготовлен в том же черновике PR #2. Рабочий сайт, Render и производственная база Supabase не изменялись. Существующие игровые расчёты, канон, тело, способности и 3D не редактировались.

Этот отчёт фиксирует P03 и проверки на момент его подготовки. P04 расширяет утверждение до рассмотрения снимка, возврата с замечанием и явной повторной отправки: [hero-review.md](hero-review.md). Текущие проверки и ближайшие этапы указаны там и в [development-status.md](development-status.md).

## Поведение

Главный ГМ выдаёт помощнику отдельные разрешения в каждом лобби: сцены, NPC, утверждение героев, экономика, раунды, переданные герои, восстановление/откат и секретные материалы. Новое назначение помощником не выдаёт разрешений автоматически. Существующие помощники после будущего обновления также начнут без разрешений: главный ГМ назначает нужные явно. При передаче роли главного ГМ прежний главный сохраняет ранее имевшиеся полномочия как помощник данного лобби; новый главный может сократить их.

Отдельно работают редактирование сцен, утверждение героев, чтение секретной копии и назначения управляющего переданными героями. Редактор сцен отдаёт только сцены, имена и портреты: полные листы, каталог, журналы и часы кампании в этот ответ не входят. Его запись изменяет только `campaign.scenes`, проверяет ссылки, общий лимит мира и ревизию. Управление сценами подразумевает доступ ко всем схемам сцен, в том числе пока скрытым от игроков. Это подготовка/расстановка мастера, а не игровая команда движения.

Секретные материалы дают чтение полного мира и скачивание копии. Без остальных разрешений интерфейс восстановления и общий редактор не открываются. Существующий общий редактор может менять всю кампанию, поэтому помощнику для него нужны все восемь разрешений. Независимых инструментов NPC, экономики, новых раундов и переигровки пока нет; их разрешения сохранены для следующих этапов и сами эти инструменты не создают.

Владелец героя явно нажимает «Передать героя мастеру» и подтверждает последствия. Собственность, исходный облачный лист, состояние героя и начатые применения сохраняются. Главный ГМ становится управляющим и может назначить **одного** помощника с разрешением `controlDelegated`. Владелец продолжает видеть состояние героя и может забрать управление без согласия мастера, в том числе в закрытом лобби. Отключение от сайта не создаёт согласия на передачу.

При отзыве разрешения, понижении роли или удалении назначенного помощника управление возвращается главному ГМ. На время блокировки аккаунта помощник также перестаёт быть действующим управляющим; после разблокировки прежнее назначение действует, если главный ГМ его не изменил. Передача главного ГМ меняет управляющего героев, порученных непосредственно главному. Если герой был явно назначен помощнику, назначение сохраняется при действующих полномочиях.

Переданные герои защищены от случайного удаления при самостоятельном выходе владельца из состава лобби: операция сообщает, что для паузы достаточно закрыть сайт, а для удаления сначала нужно вернуть управление. Явное исключение главным ГМ сохраняет прежнее поведение удаления лоббийных копий. Отдельный выход из состава кампании с сохранением героя и доступом владельца после выхода требует следующей разработки; временное отсутствие поддерживается сохранением членства.

История передачи содержит реального инициатора, тип решения, нового управляющего и время; доступна владельцу, главному ГМ и действующему назначенному помощнику. Выдаются последние 100 решений. Новые игровые заявления/команды ещё не реализованы: проверка единственного управляющего подготовлена для их серверных обработчиков. История игровых последствий и переигровки относится к следующим этапам.

## Хранение и защита

Разрешения и согласие на передачу хранятся отдельно от JSON мира в трёх таблицах приложения: `lobby_permissions`, `character_delegations`, `character_control_events`. Миграция `003-lobby-access.sql` совместима с SQLite и PostgreSQL, выполняется существующим механизмом приложения при запуске API. Это миграция приложения, не изменение облачной базы в ходе данной работы. В PostgreSQL таблицы остаются в частной схеме `world6`, с RLS и без доступа `PUBLIC`; прямые операции выполняет сервер.

Делегирование не переносится как право доступа через файл копии. При восстановлении в том же лобби текущее согласие сохраняется только для того же героя с тем же владельцем. После смены владельца согласие сбрасывается; повторное восстановление старого файла после возврата управления не передаёт героя заново. Разрешения участников из копии не восстанавливаются.

Все записи прав/управления блокируют строку лобби, повторно проверяют текущее членство, меняют ревизию и записывают аудит в той же транзакции. Старые черновики после смены управления получают конфликт версии. Гонка возврата владельцем с назначением помощника даёт одно принятое решение и один конфликт. Ошибка истории/аудита откатывает передачу целиком. Права сайта не заменяют права конкретного лобби.

Черновик ограниченного редактора сцен хранится отдельно от полного черновика, по аккаунту и лобби. Поздняя загрузка или ответ публикации не устанавливают данные в другой комнате. При потере разрешений соответствующий редактор скрывается; сохранённый полный черновик не показывается помощнику с ограниченными правами. Подтверждённые правом секреты нельзя сделать неизвестными задним числом, включая ранее скачанные копии.

## Просмотр и проверки

Локально: `npm run dev:all`. Под главным ГМ назначить помощника и открыть его разрешения; выдать только сцены и проверить отдельный конструктор. Затем выдать утверждение героев или чтение секретных материалов отдельно. Под игроком добавить облачного героя, передать его, под главным назначить помощника, отозвать разрешение и проверить возврат управляющего. Под владельцем вернуть героя и открыть историю.

- `npm test`: 53 сценария правил, без изменения прежних формул.
- `npm run test:ui`: 23 проверки, включая ограниченные права, сохранение отдельных сцен, чужой аккаунт, позднюю загрузку и ответы передачи.
- `npm run test:server`: 81 проверка; SQLite и PostgreSQL/PGlite, отсутствие самоповышения, границы лобби, секреты, сохранение мира при узкой записи, добровольность, назначения, отзыв прав, блокировка, восстановление, транзакционный откат и гонки.
- `npm run build`: TypeScript/Vite успешно. `npm run lint`: 12 прежних предупреждений, новых нет. Существующее предупреждение о крупных чанках сохраняется.

Реальный браузер, телефон, авторизованная производственная сессия и WebGL в этой среде не проверялись. UI-проверки используют jsdom. Новых зависимостей и платных ресурсов нет. `server/generated` собирается из `src` перед серверными тестами/запуском; для API нужен `server:build` либо `dev:all`.
