# «Грани Бытия»: создание и рассмотрение героев — P04

Подготовлено в том же черновике PR #2 после сцен и разрешений помощников. Рабочий сайт, Render и производственная база не обновлены. Действующие игровые формулы, канон, анатомия и 3D не менялись.

## Поведение

Главный мастер задаёт пояснения к созданию, необязательную проверку стартового ранга/ступени и список разрешённых рас существующего каталога. Пустой список оставляет выбор свободным, включая собственные расовые шаблоны. Стартовый ранг остаётся рекомендацией, пока мастер явно не включит проверку. Фильтр энергии лобби действует как прежде. Новые численные бюджеты создания или правила развития не вводятся; текстовые требования, имущество и способности проверяет человек.

Игрок сохраняет исходник в аккаунт и отправляет отдельную лоббийную копию. Заявка получает снимок отправленного листа, который не меняется вслед за правками мастера или исходника. Мастер или помощник с `approveHeroes` открывает конкретную заявку, принимает её либо возвращает с обязательным замечанием. Утверждение героя не утверждает автоматически каждую способность.

До первого принятия владелец может исправить исходник в разделе «Персонажи», сохранить его в аккаунт и явно отправить заново. Заменяется тот же герой: его ID, владелец, положение на сцене, часы и другие листы сохраняются. Подготовки, журналы игровых действий и внешние эффекты из облачного исходника не переносятся. Редактирование облачного героя само по себе не меняет кампанию.

После первого принятия замена облачным исходником закрывается даже при последующем возврате листа. Это защищает игровой прогресс; правки игрового героя выполняет мастер внутри кампании. Замена также недоступна при передаче управления, закрытии лобби или наличии действий/внешних зависимостей данного героя. Идущая кампания сама по себе не запрещает исправить ещё не принятого новичка.

Изменение условий не снимает утверждение существующих героев и не меняет их развитие. Новые условия проверяются при отправке, повторной отправке и принятии заявки. Черновики условий и замечаний сохраняются отдельно по аккаунту, лобби и герою. При смене версии сервер возвращает конфликт; черновик остаётся доступным. Загрузка свежих условий заменяет местный черновик только по явному подтверждению.

## Доступ и версии

- Замечания и оригинальный снимок доступны владельцу и уполномоченному проверяющему; прочим участникам выдаются только статус и признак запрета замены. Доступ к переданному герою или к секретным материалам сам по себе не даёт доступа к чужим замечаниям.
- Помощник с одним `approveHeroes` получает отправленный снимок без текущих правок мастера и без остальных листов мира. ID облачного исходника выдаётся только владельцу.
- Если мастер изменил текущий лист после отправки, ограниченный помощник не может принять его вслепую. Владелец повторно отправляет лист либо проверку проводит мастер с доступом к текущему листу. Отправленный и текущий варианты обозначены отдельно.
- Записи повторно проверяют членство, роль и разрешения после блокировки строки лобби. Рассмотрение, изменение условий и повторная отправка требуют актуальную ревизию; отправка также проверяет ревизию облачного исходника. Решение, лист, ревизия и аудит записываются одной транзакцией.
- Поздние ответы не устанавливаются после ухода из комнаты/аккаунта; потеря разрешения убирает интерфейс проверки. Проверки HTTP остаются обязательными независимо от интерфейса.

## Хранение, миграция и копии

`004-hero-review.sql` добавляет таблицы приложения `lobby_creation_conditions` и `character_submissions` для SQLite/PostgreSQL. В PostgreSQL они остаются в частной схеме `world6`, с RLS и без доступа `PUBLIC`. Миграция выполняется прежним механизмом приложения при запуске API; в ходе разработки облачная база не менялась.

У старых героев нет достоверного исходного снимка или истории принятия. Миграция сохраняет их игровые листы и консервативно закрывает замену исходником. Главный мастер может проверить текущий лист; ограниченному помощнику неизвестный снимок автоматически не раскрывается. Повторный запуск идемпотентен.

Объём снимков ограничен 8 МиБ на лобби отдельно от прежнего ограничения мира 8 МиБ и героя 2 МиБ. Новых зависимостей или платных ресурсов нет.

Копия лобби сохраняет необязательный `acceptedOnce`, совместимый со старыми файлами. При восстановлении существующего героя прежний запрет замены нельзя снять старым файлом. Текущий снимок и замечание сохраняются только при том же владельце; переназначение владельца удаляет прежние частные материалы заявки. Файл не импортирует условия создания, права помощников, согласие на передачу, замечания или исходные снимки. Для старого импортированного героя с неизвестной историей замена закрыта. Как и прежде, мастер с полным редактором может сознательно удалять и восстанавливать игровые листы; это отдельная операция, не повторная отправка игроком.

## Проверки и границы

- `npm test`: 53 сценария действующих правил.
- `npm run test:ui`: 27 сценариев, включая сохранение замечаний/условий, смену аккаунта/лобби, поздний ответ, отзыв права и явную отправку с версиями.
- `npm run test:server`: 105 проверок на SQLite и PostgreSQL/PGlite: весь путь заявки, разграничение данных, условия, конфликт версий, гонка принятия/отправки, сохранение сцены/времени/другого героя, защита принятого прогресса, восстановление, миграция, RLS и атомарный откат.
- `npm run build`: TypeScript/Vite; `npm run lint`: 12 существующих предупреждений, новых нет.

Это этап подготовки героя к кампании. Новый экран игрока, индивидуальные знания/видимость, движение, одновременные раунды, NPC/экономика, разговоры и голос впереди. Реальный браузер, телефон, авторизованная производственная сессия и WebGL здесь не проверялись; UI-проверки выполняются в jsdom. Общие серверные модули собираются из `src` перед запуском API и тестами.
