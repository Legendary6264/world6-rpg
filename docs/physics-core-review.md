# P1 · Физические профили и основа расчётов

5 ноября 2026 года. База: `d18cb7cb45ec8c0d8be1334e6ee01cf7c52c5961`.
Перед реализацией создана контрольная точка `checkpoint/physics-core-before-2026-11-05`.

## Что доступно мастеру

В инспекторе выбранного объекта появился закрытый по умолчанию раздел «Физические свойства»:
материал, явно заданная масса, температура и влажность поверхности. Масса не выводится
автоматически из габаритного параллелепипеда модели: это неверно для полых и составных предметов.
В разделе сцены доступны «Физические условия среды»: гравитация вниз по Z и температура.
Формы заблокированы при отсутствии права редактирования и в режиме игры.

Выбор материала показывает его плотность, удельную теплоёмкость, теплопроводность,
электропроводность, температуру исходных параметров и основание профиля.
Значения сохраняются только явной командой. Ошибочный ввод не очищает черновик.
Профиль или условия среды можно явно снять; операция входит в историю отмены.

Сейчас это сохранённые исходные данные для следующих физических модулей. Автоматические
падения, нагрев, электрические цепи, акустика и создание вещества не включены.
Существующие правила боя и решения мастера остаются в силе; канон не изменён.

## Общие модули

- `physicsUnits.ts`: единицы SI, граница абсолютного нуля, преобразование объёмов,
  масса по плотности и объёму, кинетическая энергия, импульс, изменение энергии
  при постоянной удельной теплоёмкости. Последняя формула не учитывает фазовые переходы.
- `physicsMaterials.ts`: строгая схема материала и семь независимых примеров профилей.
  Они помечены приближениями для мастера; неизвестное значение представляется `null`.
- `physicsState.ts`: версионированные профили среды и тела, проверка полей и глубокое копирование.
- `physicsEvents.ts`: контракты теплового, импульсного, материального и звукового события,
  точные временные отметки и стабильное упорядочивание. Это ещё не исполнитель событий.

Модули находятся непосредственно в `src`, как остальные общие правила проекта.
Их использует существующая сборка `server/generated`, без изменения загрузчиков всех тестов
и без добавления зависимостей.

## Материалы и граница применимости

Примеры: чистая вода, вода неизвестного состава, древесина, камень, сталь, медь и воздух.
Ни название объекта, ни его картинка не назначают материал, чистоту или массу.
Сохранённый профиль является собственным снимком, поэтому обновление каталога примеров
не переписывает параметры существующего предмета.

Для чистой воды задана слабая ненулевая проводимость при температуре профиля 25 °C.
Основание: [NIST, Low Electrolytic Conductivity Standards](https://nvlpubs.nist.gov/nistpubs/jres/100/5/j15wu.pdf).
Другие значения стартовых профилей являются игровыми приближениями.
Неизвестная проводимость не означает нулевую; проводимость сама по себе не определяет
результат электрического воздействия. Смешивание, температурные зависимости, пробой,
сопротивление контактов и электрические пути остаются для следующих этапов.

## Сохранение и совместимость

- `Scene.physics` и `SceneObject.physics` необязательны. Старые сцены сохраняют свои значения
  и не получают новые физические поля автоматически.
- Версия вложенных профилей — 1. Неизвестная версия или лишние поля внутри профиля отклоняются.
- Температура хранится в K, масса — в кг, влажность — долей от 0 до 1.
  NaN, бесконечности, отрицательная масса и температура ниже абсолютного нуля не принимаются.
- `copySceneState` копирует материал и параметры без общих изменяемых ссылок.
- Копия сцены, сборки и их предпросмотры сохраняют независимые снимки.
- Трёхсторонняя сверка сохраняет физический профиль и требует решения при конкурирующих правках.
- Архивы героев, резервные копии лобби и восстановление переносят данные как часть сцен.
- Сервер сохраняет пропущенные старым клиентом профили у существующих объектов своей сцены.
  Новое явное `null` снимает профиль. Удалённые объекты или сцены не восстанавливаются этим правилом.
- После переноса прежних полей повторно проверяется общий размер полного мира.
- Игрок не получает скрытые физические параметры через обычную проекцию мира или видимый объект.
  Доступ отдельного редактора сцен остаётся под прежними проверками разрешений.

Эти профили пока относятся к объектам сцены. Отдельное физическое состояние организма,
потоки жидкости, газовые объёмы и очередь работающей симуляции этим этапом не добавляются.

## Проверки

Добавлены 20 проверок ядра, 8 проверок форм, проверка отмены/повтора в настоящем компоненте
редактора и 16 серверных проверок с SQLite/PostgreSQL, включая родительские сценарии.

Проверяются единицы и некорректные числа; неизвестные свойства; старые сцены;
копирование без общих ссылок; сборки; сверка конкурирующих черновиков; архивы;
точные дробные отметки событий; отсутствие автоматических новых последствий;
серверные права, перезапуск, старые клиенты, атомарный отказ и восстановление.

Команды:

```sh
npm run test:physics
npm test
npm run test:ui
npm run build
npm run lint
```

Новые серверные проверки также входят в стандартный `npm run test:server`.
Перед непосредственным запуском API выполнить `npm run server:build`:
общие `.mjs` генерируются из TypeScript, часть из них не отслеживается Git.

Результаты общего прогона и список файлов записываются в `outputs/physics-core-verification.json`
и `outputs/physics-core-review.md` в рабочей папке задачи. Проверки форм используют JSDOM;
полевая проверка нового инспектора в браузере и новый GPU-тест не проводились.

## Итоговый результат

Итоговый прогон: 302 проверки правил, 571 UI-проверка и 36 серверных проверок в связанных
файлах `physics-core`, `lobby-access` и `editor-sync` прошли. Повторные 20 проверок ядра
также прошли. TypeScript и production-сборка завершились успешно. Lint — 0 ошибок,
51 прежнее предупреждение; предупреждения сборщика о крупных чанках остаются.
Полный набор `test:server` в этом этапе не запускался. Локальный API перезапущен с новыми
общими модулями и прежней тестовой базой; `/api/config` отвечает HTTP 200.
