# «Грани Бытия»: подготовка сквозной приёмки P23

Основание: согласованное ТЗ версии 1.1, разделы 14–16. Это сценарии проверки готового результата; повторный архитектурный аудит не проводится. Канон, численные правила, 3D и действующая схема доступа не меняются.

## Что сейчас можно проверить

На 11 октября 2026 года доступны база P09/P10 `8b08ebe` и отдельная подготовка бренда P22 `09d3c17`. Ранее показанный локальный код P11–P21 отсутствует. В GitHub коммит `29d6b11` не найден; найденные прежние ZIP не содержат модулей обучения, меню рабочего пространства и исполнения раундов. Для восстановления нужна сохранённая копия общего патча `grani-bytiya-local-development.patch` либо полный архив последнего проекта.

В новой ветке `feature/round-timeline-rebuild` заново подготовлен временной предпросмотр P11: [результат и ограничения](round-timeline-review.md). Это новая реализация, а не восстановление прежнего P11–P21. Исполнение P12 и фактический перенос P13 отсутствуют.

Локальные автопроверки проверяют только доступные исходники. Их общий успех не подтверждает весь P12–P21, игровую речь P25, голос P26 или прохождение P23. Браузерная приёмка всей версии требует восстановления либо новой реализации оставшихся частей.

## Воспроизводимый запуск

Node.js 24 и установленные по lockfile зависимости: `npm ci`. Затем:

```sh
npm run verify:local
```

Проверки запускаются последовательно: инструмент проверки, правила, UI, сервер, lint, производственная сборка. Серверный набор сам собирает общие правила. Все шаги выполняются даже после провала одного; итоговый код — `1` при любой ошибке. Итоговые TAP-счётчики обязательны: неполный отчёт или отменённые/пропущенные тесты не дают успеха даже при коде процесса `0`.

Каждый запуск создаёт отдельный каталог `.verification/<дата>-<идентификатор>/` с шестью логами и `summary.json`. JSON содержит команду, код/сигнал завершения, длительность, версию Node.js и текущий коммит/состояние Git. Он также явно отмечает `releaseReadiness: "not-assessed"`. Старый каталог не перезаписывается. Для выбранного нового каталога с существующим родителем:

```sh
npm run verify:local -- --output-dir /tmp/grani-check-new
```

Инструмент не запускает приложение, не подключается к рабочей базе и не публикует изменения. Он не выводит переменные окружения; логи дочерних команд сохраняются локально и не входят в Git. Состояние незакоммиченных файлов фиксируется признаком `dirty`, сами изменения не включаются в JSON.

## Условия браузерной сессии после восстановления

Использовать отдельное локальное/тестовое окружение и одноразовые данные: мастер, два игрока, помощник с ограниченными полномочиями, две кампании. Для облачной проверки использовать отдельный тестовый проект и тестовые аккаунты. Производственные данные не используются.

Открыть независимые профили браузера для всех участников. Подготовить два героя с различным заданным темпом, верхнюю и боковую сцены, NPC, скрытую область, предмет и способность с раздельной подготовкой/применением. Неутверждённые формулы задаёт мастер явно; значения тестового примера не объявляются каноном. Дополнительно проверить экран 390×844 и настоящий телефон с сенсорным вводом. Проверка 3D требует браузера с рабочим WebGL, а не JSDOM.

В каждом сценарии сохранять окружение, коммит, ожидаемый и наблюдаемый результат. Для проверки тайны смотреть также ответы API и Socket.IO: отсутствие текста на экране само по себе недостаточно. Не включать токены, секреты и данные настоящих участников в отчёт.

## Очередь продолжения

1. Продолжать новую реализацию от P11 к P12/P13 по ТЗ. Если доступен полный прежний патч/архив P11–P21, проверить его основание и пересечения в отдельной копии. Текущую ветку не сбрасывать.
2. Для каждого восстановленного или заново реализованного этапа согласовать пересечения с P22 и запустить нужные локальные наборы на фактическом объединённом коде. Число проверок старой базы не переносить в отчёт новой версии.
3. Проверить реализацию P25/P26 по фактическому коду и ближайшим открытым решениям O12/O13; не считать их завершёнными по наличию обычного чата.
4. Пройти таблицу с мастером, двумя игроками, телефоном и WebGL; исправить воспроизводимые ошибки и повторить затронутые сценарии.
5. Подготовить конкретный результат для просмотра. Публикация, новый адрес и изменения облачной конфигурации остаются отдельным согласованным шагом.
