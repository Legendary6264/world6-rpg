# Способности: оплаченные заряды, окружение и общий визуальный процесс

Этап от 4 ноября 2026 года. Основа: `6735355`. Контрольная точка до изменений: `checkpoint/abilities-before-2026-11-04`.

## Использование игроком

1. Открыть «Способности», выбрать утверждённую способность.
2. Для новой подготовки оставить «Новая подготовка / заряд из очереди этого хода». Панель показывает базовый расход; итоговый расход и личное время определяют действующие правила и подтверждение мастера.
3. Для уже оплаченной подготовки выбрать конкретный собственный заряд. Его форма, дальность и оформление берутся из сохранённого снимка. Показаны готовность, привязка, предел удержания и расход удержания, если они заданы правилом.
4. Выбрать себя, раскрытое существо либо пространственную отметку. Щелчок по предмету или существу задаёт известные координаты для пространственной способности. Прицел и список отметок внутри формы используют снимок выбранного заряда.
5. Добавить выпуск в очередь и отправить ход. Один выбранный заряд нельзя добавить дважды. Исчезнувший заряд требует нового выбора, автоматической подстановки другого нет.

Выбор сохраняется в быстрых и точных параметрах после перезагрузки. Способность, удалённая из текущего списка или снятая с утверждения, остаётся доступной только через её прежние оплаченные заряды. Создать новую подготовку из такого снимка нельзя. Подготовка и выпуск в одной очереди поддерживаются: конкретную подготовку этого хода выбирает мастер.

## Решения мастера и окружение

Заявление может содержать необязательный `castId` на этапе выпуска. Сервер проверяет принадлежность, способность и состояние заряда. В форме исполнения этот выбор зафиксирован; смена требует возврата заявления. При старом заявлении без `castId` мастер по-прежнему выбирает собственный заряд либо подготовку раньше в очереди.

У пространственного выпуска есть необязательный список последствий окружения. Для каждого мастер выбирает объект, поддерживаемую им операцию и записывает основание по правилу способности. Доступны существующие операции состояния: открыть/закрыть, запереть/отпереть, зажечь/погасить, активировать/отключить. Максимум 20 объектов, по одному изменению на объект в выпуске.

Расчёт проверяет **центр** объекта по XYZ: `x`, `y`, `z + height / 2`. Используется форма оплаченного снимка в момент выпуска, после предшествующих перемещений. Объект должен находиться в этой сцене и поддерживать операцию. Запертая дверь не открывается без отдельного отпирания; закрытие двери при расчёте движения проверяет пересечение с телами прежним механизмом столкновений. Преграды, доступность и возможность конкретного магического изменения подтверждает мастер.

Эффекты на существ и изменения объектов входят в один расчёт, предпросмотр, журнал и атомарное применение раунда. Ошибка любого последствия отклоняет весь расчёт. Повтор подтверждённой команды не применяет последствия второй раз. Снимок до раунда, резервная копия и восстановление сохраняют состояния объектов и оплаченных зарядов.

## Визуальный процесс

- SVG и WebGL используют общие персональные часы каждого выпуска. Появление эффекта другого игрока не перезапускает предыдущий выпуск.
- Ключ эффекта устойчив к перестановке персонажей/зарядов. В личную карту не передаются исходные внутренние ID, имена способностей, параметры расчёта и скрытые цели.
- Уже завершённые применения при входе на сцену остаются доступны для явного повтора. Повторный сетевой ответ и временная потеря раскрытия не создают второе применение.
- Длительный эффект показывает последовательность применения, затем остаётся в фазе остатка до окончания своего срока. Пространственный след сохраняет исходную ось после ухода применяющего.
- Пауза, выключение эффектов и скрытая вкладка сохраняют текущую фазу. В режиме уменьшенного движения показывается неподвижное воздействие; оно также завершается по длительности.
- Неизменившийся набор эффектов не пересоздаёт GPU-геометрию. Существующие пределы частиц, эффектов, локальных источников света и отсечение раскрытыми областями сохранены.

## Границы канона и проверки

Оформление само по себе не задаёт физические правила. Огонь не поджигает произвольный объект, вода не гасит всё автоматически. Новые значения урона, стоимости, времени, восстановления и баланса не вводились. Существующий движок определяет урон, лечение, состояния, модификаторы, удержание, привязку и расход ресурсов. Геометрия получателей по-прежнему проверяет отметки существ, а не пересечение анатомических объёмов. Поддерживаемые пространственные области, разрушение объектов и автоматическое решение о преградах требуют отдельного правила.
