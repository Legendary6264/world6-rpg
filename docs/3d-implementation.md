# Первая 3D-версия: карта реализации

Дата: 19 октября 2026 года. Основа аудита — актуальная GitHub main `679ab460f3e142a6883b005675b29a9b46926969`.

Целевая обычная сессия: четыре игрока и мастер. Основной испытательный ПК: Ryzen 5 7400F, RTX 2060, 32 ГБ DDR5, 2560×1440. Полноценная игра с телефона отложена.

## Результат аудита

В проекте уже реализованы регистрация и роли, сетевые лобби, независимые копии персонажей, утверждение героев, редактор сцен, координаты XYZ и опоры, адресное раскрытие карты, подготовка сцены мастером, серверный сбор заявлений, расчёт/применение раундов, перенос незавершённых действий, история, контрольные точки и восстановление. Проверки работают с SQLite и PostgreSQL.

До этого изменения игровой `SceneViewport` и личная `PerceivedScene` были SVG-схемами. Three.js использовался в других частях проекта, поэтому смена движка не нужна.

## Этап 1 — реализован в этой ветке, ожидает визуальной приёмки

- Общее 3D-представление мастера и игрока: вращение, сдвиг, масштаб камеры, возврат к общему виду, сетка, подписи, три режима качества.
- Выбор объекта/персонажа и точки земли; редактор использует прежние команды размещения, игрок — прежнюю очередь действий. Работа камеры не изменяет мир.
- Отключаемая привязка редактора с шагом 0,25 / 0,5 / 1 / 2 м. Высота не округляется автоматически.
- У игрока источник 3D — исключительно серверная `PerceivedMap`. Полный мир не передаётся в личный рендерер. Объекты обрезаются по раскрытым объёмам, запомненные состояния приглушаются, нераскрытая высота показывается условной плоской отметкой. Тени скрытой геометрии не рассчитываются.
- Низкополигональные процедурные формы для текущих типов объектов и условные фигуры персонажей. Эти модели не являются окончательным реалистичным визуалом или источником размеров анатомии.
- Отдельный шаблон `world6-3d-sandbox`, версия 1: поселение, лес/дорога и подземное сооружение. Создаётся закрытая независимая кампания, по умолчанию четыре места для игроков; допустимы Мана и Тень. Старый пример сохраняется.
- Переходы выполняются существующим запуском сцены мастером. Активный сбор и незавершённые действия защищены. Автоматическая телепортация, время перехода и бесшовная подгрузка не вводятся.
- При недоступном WebGL или потере контекста автоматически открывается прежняя схема. SVG сохраняет прежние инструменты и анимированный повтор эффектов. В 3D эффекты пока представлены статическими отметками.
- Формат сохранения сцен версии 1 сохраняется. Компоненты рендера — адаптер; авторитетные игровые сущности ещё не переведены на новую компонентную модель хранения.
- Отрисовка выполняется по изменениям камеры/сцены, без постоянного игрового цикла в клиентском рендерере. GPU-ресурсы освобождаются при смене сцены/режима и размонтировании. Производительность на целевом ПК ещё не измерена.

## Проверка этого изменения

- `npm run build` — TypeScript и клиентская сборка.
- `npm run lint` — ошибок нет; прежние предупреждения проекта остаются.
- `npm test` — общие правила и новые проверки шаблона, проекций и привязки.
- `npm run test:ui` — существующие 167 сценариев интерфейса, 4 сценария выбора ресурсов и 3 новых сценария 3D-интерфейса с подменённым GPU-рендерером. Геометрия, камера и raycasting в новых сценариях используют настоящий Three.js; проверяются выбор объекта, координаты точки земли, обновление callbacks без пересоздания рендера, отсутствие постоянной отрисовки, маркер XYZ, смена качества, освобождение ресурсов, обрезка по раскрытию и уведомление о потере контекста. В JSDOM проверяется автоматический переход к SVG при недоступности WebGL.
- `npm run server:build` и `node --test --test-concurrency=2 server/test/*.test.mjs` — 525 проверок сервера, включая отдельную сессию мастера с четырьмя игроками на SQLite и PostgreSQL, три области, изоляцию NPC, теневого героя, лимит мест, повтор применения и перезапуск.

Ограничение проверки: браузер с WebGL локально недоступен; попытка установить Chromium не дала корректного архива, облачный браузер не имеет доступа к локальному dev-серверу. Поэтому реальная WebGL-отрисовка, внешний вид, работа камеры/выбора на GPU и FPS не подтверждены. До выпуска необходима визуальная проверка в браузере с аппаратным ускорением.

Изменения предназначены для просмотра в отдельном draft PR. Рабочая БД, Render и основная ветка в рамках этапа не изменяются.
