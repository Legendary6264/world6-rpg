# Первая 3D-версия: карта реализации

Дата: 19 октября 2026 года. Основа аудита — актуальная GitHub main `679ab460f3e142a6883b005675b29a9b46926969`.

Целевая обычная сессия: четыре игрока и мастер. Основной испытательный ПК: Ryzen 5 7400F, RTX 2060, 32 ГБ DDR5, 2560×1440. Полноценная игра с телефона отложена.

## Результат аудита

В проекте уже реализованы регистрация и роли, сетевые лобби, независимые копии персонажей, утверждение героев, редактор сцен, координаты XYZ и опоры, адресное раскрытие карты, подготовка сцены мастером, серверный сбор заявлений, расчёт/применение раундов, перенос незавершённых действий, история, контрольные точки и восстановление. Проверки работают с SQLite и PostgreSQL.

До этого изменения игровой `SceneViewport` и личная `PerceivedScene` были SVG-схемами. Three.js использовался в других частях проекта, поэтому смена движка не нужна.

## Этап 1 — реализован в этой ветке, ожидает визуальной приёмки

- Общее 3D-представление мастера и игрока: вращение, сдвиг, масштаб камеры, возврат к общему виду, сетка, подписи, три режима качества.
- Выбор объекта/персонажа и точки земли; редактор использует прежние команды размещения, игрок — прежнюю очередь действий. Работа камеры не изменяет мир.
- Отключаемая привязка редактора с шагом 0,25 / 0,5 / 1 / 2 м. Высота не округляется автоматически.
- У игрока источник 3D — исключительно серверная `PerceivedMap`. Полный мир не передаётся в личный рендерер. Объекты обрезаются по раскрытым объёмам, запомненные состояния приглушаются, нераскрытая высота показывается условной плоской отметкой. Тени скрытой геометрии не рассчитываются.
- Низкополигональные процедурные формы для текущих типов объектов и условные фигуры персонажей. Эти модели не являются окончательным реалистичным визуалом или источником размеров анатомии.
- Отдельный шаблон `world6-3d-sandbox`, версия 1: поселение, лес/дорога и подземное сооружение. Создаётся закрытая независимая кампания, по умолчанию четыре места для игроков; допустимы Мана и Тень. Старый пример сохраняется.
- Переходы выполняются существующим запуском сцены мастером. Активный сбор и незавершённые действия защищены. Автоматическая телепортация, время перехода и бесшовная подгрузка не вводятся.
- При недоступном WebGL или потере контекста автоматически открывается прежняя схема. SVG сохраняет прежние инструменты и анимированный повтор эффектов. В 3D эффекты пока представлены статическими отметками.
- Формат сохранения сцен версии 1 сохраняется. На этапе 3 добавлено параллельное компонентное хранение; прежний JSON пока остаётся авторитетным.
- Отрисовка выполняется по изменениям камеры/сцены, без постоянного игрового цикла в клиентском рендерере. GPU-ресурсы освобождаются при смене сцены/режима и размонтировании. Производительность на целевом ПК ещё не измерена.

## Этап 2 — реализован совместимый компонентный каркас

- `worldEntities.ts` описывает версионированные компоненты персонажей, объектов и сцен. У персонажа разделены идентификация/профиль, атрибуты, ресурсы, развитие, знания, анатомия, правила и позиция. У объекта разделены идентификация, позиция, геометрия, коллизии и оформление.
- Адаптер сохраняет порядок сцен, объектов и токенов, опоры и дробные координаты. Составные ID различают одинаковые локальные ID объектов в разных сценах. Дополнительные поля старого формата сохраняются в `extensions`; они не могут подменять известные поля.
- Все 16 существующих мест записи текущего `world_json` в 13 серверных модулях используют `commitWorld`: общая валидация, проверка обратимости компонентного представления и compare-and-swap по ревизии. Права, квитанции, аудит и история проверяются в прежних транзакциях; уведомление клиентам остаётся после успешного commit.
- На этапе 2 снимок компонентов и дельта изменений вычислялись в памяти на границе команды. Дельта различает создание, удаление и изменение компонентов; порядок ключей JSON не создаёт ложного изменения. Постоянное хранение добавлено следующим этапом, описанным ниже.
- Полный `GET /api/lobbies/:id/entities` доступен только участнику с `viewSecrets`. Игрок продолжает получать только `PerceivedMap`. Мастерское 3D использует общий адаптер компонентной геометрии объектов.
- Точные байты действующего сохранения и исторические снимки не переписываются при чтении или переходе через адаптер. На этапе 2 после перезапуска компонентное представление собиралось из подтверждённого мира в БД; этап 3 читает сохранённые компоненты с проверкой совместимости. Отдельная миграция рабочей БД не выполнялась.
- Правила, сборка и 174 интерфейсные проверки прошли. Для компонентного адаптера добавлены 7 сценариев; серверные проверки расширены до 539, включая конфликт одновременных команд, точные байты сохранения, откат при сбое аудита, права полного снимка и перезапуск на SQLite и PostgreSQL.

## Этап 3 — постоянные компоненты и история реализованы в ветке

- Отдельные сущности и компоненты с версиями, типами, связями, порядком; JSONB в PostgreSQL, JSON в SQLite. Закрытая схема, RLS, индексы по ключам и контроль согласованности с исходным JSON.
- Постепенный перенос выбранной кампании главным ГМ либо при первой записи мира, без массового преобразования при запуске. Исходные байты сохраняются в базовом событии; чтение и повтор переноса ничего не переписывают.
- Атомарная запись мира, компонентов, дельт, истории, квитанций и аудита. Неизменяемый журнал результатов с восстановлением без нового исполнения правил. События защищены триггерами; переполнение лимита 64 МиБ отменяет всю команду.
- Защищённые API проверки состояния, переноса и выгрузки исходника/компонентов/журнала. Права игроков не расширены. Панель управления переносом пока не добавлена.
- Перезапуск, смена прав без изменения мира, создание/удаление/порядок, конфликты, сбои записи и восстановление проверены на обеих БД. Прежний JSON остаётся авторитетным на период перехода.
- Бакет для крупных новых ресурсов и выгрузка тяжёлых вложений остаются открытой частью этапа 3/7. Существующее оформление переносится без изменения. SQL рабочей БД и Render не изменены.

Подробности границы совместимости: [component-runtime.md](component-runtime.md).

## Проверки этапов 1–3

- `npm run build` — TypeScript и клиентская сборка.
- `npm run lint` — ошибок нет; прежние предупреждения проекта остаются.
- `npm test` — общие правила и новые проверки шаблона, проекций, привязки и компонентного адаптера.
- `npm run test:ui` — существующие 167 сценариев интерфейса, 4 сценария выбора ресурсов и 3 новых сценария 3D-интерфейса с подменённым GPU-рендерером. Геометрия, камера и raycasting в новых сценариях используют настоящий Three.js; проверяются выбор объекта, координаты точки земли, обновление callbacks без пересоздания рендера, отсутствие постоянной отрисовки, маркер XYZ, смена качества, освобождение ресурсов, обрезка по раскрытию и уведомление о потере контекста. В JSDOM проверяется автоматический переход к SVG при недоступности WebGL.
- `npm run server:build` и `node --test --test-concurrency=2 server/test/*.test.mjs` — 570 проверок сервера, включая отдельную сессию мастера с четырьмя игроками на SQLite и PostgreSQL, три области, изоляцию NPC, теневого героя, лимит мест, повтор применения и перезапуск.

Ограничение проверки: браузер с WebGL локально недоступен; попытка установить Chromium не дала корректного архива, облачный браузер не имеет доступа к локальному dev-серверу. Поэтому реальная WebGL-отрисовка, внешний вид, работа камеры/выбора на GPU и FPS не подтверждены. До выпуска необходима визуальная проверка в браузере с аппаратным ускорением.

Изменения предназначены для просмотра в отдельном draft PR. Рабочая БД, Render и основная ветка в рамках этапа не изменяются.
